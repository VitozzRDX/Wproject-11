## Архитектура
```
Click → Interpreter (RULES matching) → Engine (handlers) → State ←→ Renderer/Positioning/RendererUI
                                                        → UIState (events для UI) → RendererUI
                                                        → Rules (чистая математика, mutations в engine)
```

- **State** — данные + subscribers (fire только на setUnit). Есть window.State для дебага.
- **Rules** — чистая математика; НЕ импортит State (elr и др. передаётся через unit-поля).
- **Engine** — единственный кто мутирует State; вызывает Rules и применяет результаты.
- **UIState** — event bus для UI-эффектов (flashLOS, flashHitPoints, setResidualFP, setSmoke, addButton, removeButton).
- **RendererUI** подписан на UIState.
- **Renderer** подписан на State.setUnit (subscribers pattern).

## Единая иерархия юнитов (unitloading.js)
Всё в одном `TEMPLATES` + `State.units`, различие по `category`:
```
Unit (base)
├── Infantry (category='infantry')
│    ├── Squad, HalfSquad
│    └── Leader (SMC)
└── CarriedItem (category='carried', possessorId)
     └── SW → MG (LMG/HMG etc.)
```
- `broken` живёт per-category: у Infantry = morale-broken, у CarriedItem = jam/malfunction.
- `possessorId` только у carried; hex наследуется от possessor'а.

### Defensive First Fire
- Полный пайплайн: LOS, TEM, HA, hindrance, FFNAM, FFMO, leadership DRM
- IFT resolution, `calcFireEffect` returns `{ effect, baseDr, coloredDie }`
- MC/PTC/KIA/K/ processing (все филтрят carried)
- `_processMC` умеет: leader help pool, broken → CR, wound severity, pinned на marginal pass
- `_processPTC` аналогично (leader help)
- `_woundLeader`: мутирует morale-1, leadershipModifier+1, mf=3, wounded=true
- Cascade **LLMC → LLTC** через `_checkLeaderLoss` (loop-until-stable, Set triggered)
- KIA-survivor → broken + DM (`_placeDM`)
- NMC-fail → broken + DM + clear pin/CX
- Original 12 rules: broken+12 → CR + possible quality reduce chain
- Cowering: doubles + no leader in FG → column shift left
- TPBF (same hex), PBF, Area Fire
- Правило 3.3.3: `fired_from_on_target_in_hex` count + firers per shooter hex
- Правило 3.2.2: same-hex separate attack blocked

### Multi-hex FG + splitting
- `State.fireGroupHexesArray` — уникальные хексы стрелков (заполняется в `_addToFireGroup`, чистится вместе с fireGroup)
- `Rules.filter_hexes_with_Los(hexes, targetHex)` — отсеивает без LoS/hindrance
- `Rules.array_of_adjacent_Hexes_arrays(validHexes)` — BFS-разбиение на sub-FGs по соседству
- Engine DFF handler:
  1. Фильтрация LoS → validHexes.
  2. Разбиение на components.
  3. Sequential fire по каждой sub-FG с реальными анимациями между ними (`await _apply_changes_for_targets`).
  4. firingStatus counters только тем, кто реально стрелял (Set `firedUnits`).
  5. weaponsKeepingRoF накапливается — эти не бампаются.

### Fire counters + weapons
- `firingStatus`: ' ' → 'FirstFire' → 'FinalFire'
- SFF: FirstFire → halved FP, normal range only, closest KEU check
- FPF: FinalFire → halved FP + adjacent/same hex only + self-NMC после огня
- `_check_SFF_valid` + `_check_FPF_valid` precondition в defensiveFF
- FPF self-NMC использует `_processMC(subjects, 0, changes, baseDr)` с fixedDr
- **Weapon FG membership** (`checkIfAddingToFireGroupIsValid`): для carried требует possessorId + possessor не broken/pinned; nation берётся у possessor'а (трофейное).
- **`calcFirepower`**: `if (unit.broken) return 0` для weapon/infantry.
- **B# malfunction** (`_calc_malfunction`): `baseDr >= B# - (SFF/FF penalty 2)` → weapon.broken=true.
- **RoF preservation** (`_calc_weapons_kept_RoF`): `coloredDie <= rof` AND не сломан → не бампаем firingStatus.
- **Weapon drop при elim possessor'а**: `_remove_unit` сбрасывает possessorId=null, снимает MG/FG рамки, перепозиционирует хекс. Reduce (не elim) — possessor переносится через `inheritedWeapons` в `_replace_unit`.

### Residual FP (3.3.5)
- `State.residualFP` — `{ "col,row": fp }`.
- `_calc_residual_FP(fg, targetHex, hindrance, brokenWeapons, keptRoF)` — FP исключает malfunctioned/keptRoF. Column shift за: positive leader DRM, CX shooter, hindrance > 0.
- `defensiveFF` возвращает `residualFP`. Engine обновляет `State.residualFP[hexKey]` (больший заменяет меньший) + `UIState.setResidualFP` → renderer рисует.
- `Rules.residualAttack(fp, targets, targetHex)` — атакует всех вошедших юнитов одной IFT DR при движении. Триггерится в `_apply_movement_result_in_State_for_all_MG` после setUnit(hex) → `await _apply_changes_for_targets`.
- **Визуал:** красная 12-конечная звезда (Konva.Line с jitter'ом, seed от хекса) с текстом `Residual / Fire / N` в центре гекса. `residualNodes` Map в rendererUI.

### ELR (5.1)
- `State.elr = { german: 3, soviet: 3 }` (init в state.js).
- `unit.elr` присваивается в `createAndLoadUnits`/`spawn_unit`: `template.lowerQuality ? State.elr[nation] : 20`.
- Chain `lowerQuality` в шаблонах: `ge_468 → ge_467 → ge_447 → ge_436`; `ge_548 → ge_447`; russian similar. Conscript (последний в chain) без lowerQuality → elr=20 (эффективно ∞).
- **`_processMC`** — новые ветки:
  - `finalDr - morale > u.elr` → `'quality_reduce'`.
  - original 12 + failedBy > ELR → `'reduce_then_quality'` (chained).
- **Engine `_apply_changes_for_targets`** handlers:
  - `'quality_reduce'` — сначала broken-флип, потом `_replace_unit(id, u.lowerQuality, id)`.
  - `'reduce_then_quality'` — broken-флип, потом CR (`_replace_unit(id, u.halfSquad, id)`), потом quality reduce на новом HS.
- Leaders/HS с morale underlined — не подвержены (нет `lowerQuality` → elr=20).

- **Placement (только свой hex, 1 MF, MVP):**

### LOS (pixel-based)
- `terrainLOS.js` — модуль с `initTerrainLOS()` и `pixel_is_on_Obstacle_set(type, x, y)` + `bresenham()` + `getLastHit()/setLastHit()`.
- `terrainPixels.json` сгенерирован через `extract_contours.html` (для V-карты + U-карты).
- `roadPixels.json` — отдельный, для Orchard-Road shield.
- V-карта повёрнута 180° — `cards.js` мержит статику через rotation.
- Woods PNG почищен через `scripts/clean_terrain_pixels.js` (одноразовая утилита, вычитает orchard-пиксели и false-hexes).
- `terrainAt(col, row)` теперь также мержит `State.dynamicTerrain` (smoke).

### checkLOS (hex-based)
- `Rules.checkLOS(fromHex, toHex)` — чистая геометрия, возвращает bool. Hindrance-порог (>=6) вынесен в вызывающих.
- OBSTACLES = ['woods', 'buildings', 'hills']. Правила:
  - hills блок → если LoS involves ground-юнит.
  - woods/buildings блок → если pixel-hex на hill (level-2 obstacle) ИЛИ хотя бы один юнит на ground.
  - crestLine treated as level 1 (consistent с calcElevation).

### checkHindrance
- `Rules.checkHindrance(shooterHexes, targetHex)` — hex-based.
- `_los_stays_on_road_in_Orchard(shooterHex, targetHex, hexPath)` — tree-lined road shield (весь путь orchard-road + LoS не пересёк road-контур).
- В планах интегрировать `_calcSmokeDRM` (TODO шаг C для smoke).

### Height Advantage
- `Rules.calcHeightAdvantage(shooterHexes, targetHex, hexUnits)` — HA +1 если target выше, TEM=0, минимум одного стрелка ниже.
- Exception: если ВСЕ shooter'ы имеют LoS-entry hexside == move-crest hexside (unit пересекает crest line в target через тот же hexside, что и LoS) → HA снимается.

### Калибровка гексосетки (hexUtils.js)
- `RX = 37.30`, `GRID_OFFSET_X = 1.32`, `DRIFT_COEF = 0.005`, `DRIFT_COEF_LEFT = 0.010`
- `colToLetters` формат: `AA, AB, AC, ...` (последовательные, НЕ `AA, BB, CC`)
- `pixelToHex` итеративная коррекция для дрифта
