## Архитектура
```
Click → Interpreter (RULES matching) → Engine (handlers) → State
                                             → UIState (event bus) → RendererUI
                                             → Rules (чистая математика)
```

- **State** (state.js) — данные + subscribers. `window.State` доступен.
- **PhaseManager** — фазы: `setup`, `rally`, `prepFire`, `movement`, `defensiveFire`, `advancingFire`, `rout`, `advance`, `closeCombat`.
- **Rules** (rules.js) — чистая математика, НЕ импортит State.
- **Engine** — единственный кто мутирует State.
- **UIState** — event bus.
- **Запрет**: main.js ↔ engine.js прямых импортов нет. engine может импортить чистые хелперы/константы из rendererUI (geometry) и renderer (visual helpers), но взаимодействие с UI идёт через UIState-ивенты.
- **Слои Konva:**
  - `backgroundLayer` — карта + hex-grid.
  - `ccLayer` — world-anchored под юнитами (CC-подсветка).
  - `unitLayer` — юниты на карте.
  - `worldFxLayer` — LoS, residual, smoke, rout, setup-bounds, hover-FP.
  - `uiLayer` — screen-fixed: кнопки, крутилка, dice, Turn-text, Hill/VP-counter, setup-панель, пул-юниты (во время setup), группы-панели, target-панель, VS-панели CCPh, planks.

## Фазы

### Setup
- `setupPhase.js`: см. предыдущую версию контекста. Пре-спавн юнитов, pool/map модель.
- `applyDiceRoll` ставит `alliedVpTarget` из `winConditions.atGameEnd.targets[roll]`, вызывает `UIState.setAlliedVPText` если цель задана.

### Rally — без изменений.

### MPh
- `_apply_movement_result_in_State_for_all_MG`: обновление mf/бонусов + `_updateHexControl(targetHex)` + `_eliminateIfOutOfBounds(uid)` для вошедших + `_refreshGroupPanel()`.
- `_applyMPhStartCXCleanup` при NextPhase→movement.
- Конец MPh: hasStartedMoving/movementCompleted/wasExhaustedLastTurn/doubleTime очищаются. `_refreshGroupPanel()` после очистки MG.

### PFPh / DFPh / AFPh
- `_handleFire` возвращает dice + создаёт target-панель (before/after + KIA/pin/wound).
- Assault Fire (A8.3): после всех модификаций FP (включая дистанционный множитель) squad с `underlinedFP` в пределах normal range получает +1, дробь округляется вверх.
- Hover FP: `interpretHover(hex)` → `Engine.handlers.HoverFireTarget` → `UIState.setHoverFP(hex, fp)` → мировой текст над hex'ом в огневой фазе при непустой FG.

### RtPh
- `_eliminateIfOutOfBounds` вызывается при RtPh move.

### APh
- Advance handler проверяет `Rules.checkOverstack` (per-side).
- APh reset: sets mf=baseMF (wounded leader min(mf,3)), `leaderBonus = baseLeaderBonus`, `roadBonus = baseRoadBonus`, `usedWoodsRoad = false`.
- `_eliminateIfOutOfBounds(uid)` после advance.
- Выход из APh: сброс `assaultMovement`.

### CCPh (переработано)
- SelectCCHex: правило срабатывает и по клику на юнита (убрали `notUnit` guard).
- При входе: показываются VS-панели (пусто изначально), главный CCPanel с юнитами.
- Если hex ambush-eligible → показывается `RollAmbush` под NextPhase (x=10, y=56). `State.ambushPending=true` блокирует клики по юнитам/Confirm до ролла (interpreter guard).
- После RollAmbush:
  - Успех → `State.ambushSide='attacker'|'defender'`, `ccAmbushRound='round 1'`, `ccDefenderDeclaring` по стороне, кнопка `StartCC` (label 'StartCC', text 'Roll Close Combat !').
  - Неуспех → `showActiveSidePlank({slot:0, badge})` — белая планка (прозрачность 0.7) «[значок] choose Close Combatants :» в слоте 0.
- CCToggleUnit: клик по юниту в CCPanel добавляет в текущий пул (`ccAttackerAttackers`/`ccAttackerDefenders` или defender аналог). `_refreshCCConfirmButton` + `_refreshCCPanels`.
- Confirm handler (ex-ConfirmCCAttack): фиксирует атаку из активных пулов в `ccAttackerList` или `ccDefenderList`. В non-ambush attacker-declare mode: после первой атаки показывает `StartDefenderCC` (внизу экрана, y = window.innerHeight-46).
- StartDefenderCC: ручной переход в defender declare через `_swapToDefenderDeclare`.
- `_swapToDefenderDeclare`: `ccDefenderDeclaring=true`, свежий `ccSelectedIds`, StartCC кнопка, вторая планка «[значок defender] choose Close Combatants :» в слоте `ccAttackerList.length + 1`.
- ConfirmCCDefend handler (отдельный, но button-label тоже 'Confirm' через `text` в def): для defender declare. Не делает auto-swap.
- StartCC handler = ResolveCC: `_result_of_CC_in_hex` (non-ambush) или `_resolveAmbushRound` (ambush).
- Target-панель результатов CC: `_snapshotTargetsBeforeFireEffect` в SelectCCHex (на `ccHexParticipants`), после резолва в `_finalizeCCHex` — snapshot after + `_createTargetPanel` + `UIState.showTargetPanel(panel)`.

## Сетка CC-слотов (унифицированная)
- `CC_PANEL_X=10, CC_PANEL_Y=62, CC_PANEL_STEP_Y = CC_PANEL_H + CC_PANEL_GAP_V` (константы в rendererUI).
- Слот 0 — первая планка (RollAmbush fail или ambush-first side).
- Слоты 1..N — attacker VS-панели (или первой-декларирующей стороны).
- Слот N+1 — вторая планка (defender choose...).
- Слоты N+2.. — defender VS-панели.
- Confirm — справа от последней VS-панели (x = `CC_CONFIRM_X`, y = CC_PANEL_Y + lastSlot*STEP).
- `_buildVSPanelsData` в engine возвращает `[{slot, left, right}]`. drawCCAttackPanels использует `panel.slot` для y.
- Экспорты из rendererUI: `getCCConfirmButtonPos(slot)` → `{x, y}`.

## Контроль гексов и VP
- **A26 Control** — как раньше. `_updateHexControl`, `_refreshHexControlCounter`.
- **VP двусторонние:** State.alliedVP, axisVP, alliedVpTarget, axisVpTarget (все null/0 по умолчанию). UI показывается только если сценарий поставил цель.

- `_eliminateIfOutOfBounds(unitId)` — чистая проверка + вызов `_killUnit` с `cause:'oob'`.
- `_isOutOfBounds(hex)` — чистый предикат.
- `State.deadUnitImages: {id: imageRef}` — снимок иконки на момент `_remove_unit`. Нужно target-панели и VS-панели CC чтобы рисовать KIA после удаления юнита. Сбрасывается на loadScenario и load.

## Rules / Mechanics
- `isHexInSetupZone(nation, hex)` в engine.
- `_isRoadHex(hex)` safe for null hex.
- `checkOverstack(targetHex, mg, units)` — **per-side**: считает только юниты той же стороны что mg[0]. Экспортирована через Rules.
- `calcFireEffect` возвращает `coloredDie, whiteDie`.
- `fireAttack` возвращает те же поля + rolls (per-target). 
- `calcFirepower`: Assault Fire после всех модификаций (fp halved в AFPh → distance mult → +1 ceil для `underlinedFP` squad в normal range).
- `_applyCowering` негирует cowering при ЛЮБОМ лидере в FG.
- `mustRout` (b): `openGround = terrain.every(t ∈ {crestLine, hill, dirtRoad, pavedRoad})`. Фильтр shooters: broken/pinned/leader/no FP пропускаются. Height Advantage skip: если `calcHeightAdvantage([shooter.hex], unit.hex, [unit]) > 0` — не mustRout по этому стрелку.
- `_portageExcess` SMC-бонус MMC с наибольшим excess.
- `calcHeightAdvantage` — level 1 если terrain содержит 'hill' или 'crestLine'; crestLine-exception при movement.
- `_hexLine` дедуплит повторы hex'ов (spine-pick может возвращать один hex много раз, что раньше ломало `checkHindrance`).
- Woods-Road: `MOVE` handler игнорит клики пока `pendingMove` активен. `road_bonus_is_possible` требует `_all_path_is_road(u.path) && !u.usedWoodsRoad`.
- `wounded` leader original-12 flow: `broken` синкается через `State.setUnit` в `_apply_changes_for_targets` (строка `if (u && u.broken && state !== 'broken')`).
- `hasLeader(mg, units)` экспортирован.
- `_all_path_is_road(path)` экспортирован.
- `calcFirepower` экспортирован (для hover-FP).
- Interdiction: HA-eligible unit immune (симметрично mustRout).
