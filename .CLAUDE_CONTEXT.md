# Контекст проекта — Wproject11 (ASL SK)

## Общее
- **Директория:** D:/Wproject11
- **Ветка:** `defensivefire`
- **Репо:** https://github.com/VitozzRDX/Wproject-11
- **Тесты:** `npm test` (vitest), 12/12 проходят
- **Стек:** Vanilla JS + Konva.js (загружается с CDN), ES modules, Vitest

## Архитектура
```
Click → Interpreter → Engine → State ←→ Renderer/Positioning/RendererUI
                            → UIState → RendererUI (кнопки)
```
- **Rules** — чистая математика (правила ASL), возвращает планы, не мутирует State (кроме `_woundLeader` — там мутируем `u.wounded/morale/leadershipModifier/mf`)
- **Engine** — единственный кто пишет в State
- **State** — данные + subscribers pattern
- **Renderer/RendererUI** — слушают State/UIState через `subscribe`

## Реализовано

### Движение
- Per-unit MF, leaderBonus (2 для squad), roadBonus (1)
- Reactive бонусы (leader/road)
- Woods-Road (path с `{hex, isRoad}` — Phase 2)
- crestLine (double cost при подъёме)
- Overstack (3 squad + 4 leader)
- Split MG (original_group/splitted_group/moved_movement_group)
- Double Time (+2 MF, exhausted = CX text)
- Assault Movement (1 шаг, не съест весь MF, negates FFNAM)
- PlaceSmoke (тратит 1 MF через `_expend_mf`)
- `mf_spent_in_current_hex` (накопительный)

### Defensive First Fire
- Полный пайплайн: LOS, TEM, HA, hindrance, FFNAM, FFMO, leadership DRM
- IFT resolution, `calcFireEffect` returns `{ effect, baseDr }`
- MC/PTC/KIA/K/ processing
- `_processMC` умеет: leader help pool, broken → CR, wound severity, pinned на marginal pass
- `_processPTC` аналогично (leader help)
- `_woundLeader`: мутирует morale-1, leadershipModifier+1, mf=3, wounded=true
- Cascade **LLMC → LLTC** через `_checkLeaderLoss` (loop-until-stable, Set triggered)
- KIA-survivor → broken + DM (`_placeDM`)
- NMC-fail → broken + DM + clear pin/CX
- Original 12 rules: broken+12 → eliminated, unbroken+12 → CR+broken
- Cowering: doubles + no leader in FG → column shift left
- TPBF (same hex), PBF, Area Fire
- Правило 3.3.3: `fired_from_on_target_in_hex` count + firers per shooter hex
- Правило 3.2.2: same-hex separate attack blocked

### Fire counters
- `firingStatus`: ' ' → 'FirstFire' → 'FinalFire'
- SFF: FirstFire → halved FP, normal range only, closest KEU check
- FPF: FinalFire → halved FP + adjacent/same hex only + self-NMC после огня
- `_check_SFF_valid` + `_check_FPF_valid` precondition в defensiveFF
- FPF self-NMC использует `_processMC(subjects, 0, changes, baseDr)` с fixedDr

### Визуал

## Правила (rules_task.txt)
Файл содержит цитаты правил ASL SK по которым делали реализацию.

### LOS (pixel-based)
- `terrainLOS.js` — модуль с `initTerrainLOS()` (async fetch `terrainPixels.json`) и `checkLOSCrossings(from, to, excludeHexes)`
- Bresenham итерация пикселей + Set-lookup по каждому типу террейна
- `terrainPixels.json` сгенерирован через `extract_contours.html` — extract утилита читает PNG'и (`graf/woods_outline.png`, `buildings_outline.png`, `hills_outline_1.png`, `orchard_outline_1.png`, `brush_outline.png`) через canvas.getImageData, дампит `[x,y]` с alpha > 0
- Оверлеи-PNG'и накладываются на карту в `load_and_draw_background` (полупрозрачные контуры террейна)
- `checkLOS` в `rules.js` использует `checkLOSCrossings` — блокирует если `woods` или `buildings` пересечены (target/shooter hex исключаются)
- `TODO: hills` — нужна elevation logic (сравнение высот)
- **Debug:** `lastHits` экспортируется, в Engine после DFF передаётся в `UIState.flashHitPoints()` → зелёные точки на карте где LOS зацепил контур

### Калибровка гексосетки (hexUtils.js)
- Гексосетка рисуется в `main.js` `draw_hex_grid` (полупрозрачные `Konva.RegularPolygon` rotation=30 flat-top)
- Развязали `GRID_OFFSET_X` от формулы (было `RX - COL_STEP/2 - 5`) — теперь фиксированное число
- Добавили **`DRIFT_COEF`** (квадратичный компонент): `x(col) = GRID_OFFSET_X + col * COL_STEP + col² * DRIFT_COEF`
- `pixelToHex` использует итеративную коррекцию для обратного отображения
- Текущая настройка: `RX = 37.30`, `GRID_OFFSET_X = 1.32`, `DRIFT_COEF = 0.005` (эмпирически)
