## Архитектура
```
Click → Interpreter (RULES matching) → Engine (handlers) → State
                                             → UIState (event bus) → RendererUI
                                             → Rules (чистая математика)
```

- **State** (state.js) — данные + subscribers (fires on setUnit). `window.State` доступен.
- **PhaseManager** — фазы: `setup`, `rally`, `prepFire`, `movement`, `defensiveFire`, `advancingFire`, `rout`, `advance`, `closeCombat`.
- **Rules** (rules.js) — чистая математика. Импортит `PhaseManager`, НЕ импортит `State`.
- **Engine** — единственный кто мутирует State.
- **UIState** — event bus для UI (кнопки, крутилка, LoS, residual, smoke, rout/CC overlays, panels, badges).
- **RendererUI** подписан на UIState, использует слои:
  - `uiLayer` — screen-fixed (кнопки, крутилка, CC/Transfer/Setup панели, side-badges).
  - `worldFxLayer` — world-anchored выше юнитов (LoS, residual, smoke, rout overlays).
  - `ccLayer` — world-anchored под юнитами (CC-хекс красная подсветка).
- **Renderer** подписан на State.setUnit.
- **Positioning** — стэкинг юнитов в hex'e.

## Coordinate System
- Единая нумерация `"col-row"` (dash, не comma — smoke overlay чинился из-за этого).
- `pixelToHex` — Voronoi-nearest.
- `hexDistance` — cube-based.
- `_hexLine` — pixel Bresenham + hex-spine resolution.
- `cubeRing`, `dijkstraHexes`, `reconstructPath`.

## Scenarios (scenarios.js)
Модуль-левел `A_CARDVISUALS` и `A_UNITS` переиспользуются между A и A_snapshot.

- **A** — боевой: `units: []`, есть `setup:` блок (defender → attacker). Defender: pool `ge_447 ×1`. Attacker: `diceRoll` d6 → 1-3: am_667 ×2, 4-6: am_667 ×1.
- **A_snapshot** — тестовая расстановка (A_UNITS pre-filled, без setup). Запуск через `Game.loadScenario('A_snapshot')`.

Scenario record поддерживает `state:` override. `main.js`: если `scen.setup` → `setPhase('setup')` + `startSetup(scen)`; иначе → `setPhase('rally')`.

## Фазы

### Setup (новая стартовая, если у сценария есть `setup:` блок)
- Модуль **setupPhase.js**: `startSetup`, `initSetupSide`, `applyDiceRoll`, `placeFromPool`, `pickUpToPool`, `refreshSetupPanel`, `refreshEndSetupSideButton`.
- Порядок сторон задаётся `scen.setup.order`. Для каждой: либо прямой `pool`, либо `diceRoll{dice,outcomes}` (`'1-3':[...]`).
- UI: `UIState.showSetupPanel(pool)` — тёмный бокс с thumbnails. Клик на юнит в боксе → `setupSelectedTemplate`. Клик на карту → `placeFromPool` (spawn + splice из pool). Pick-up: `pickUpToPool`.
- Кнопка `EndSetupSide` появляется только когда pool пустой И (dice уже брошен ИЛИ его нет вовсе). Иначе — `needsRoll=true`, кнопка скрыта.
- `RollDice` показывается если `sideCfg.diceRoll && !setupDiceRolled`.
- `endSetupSide` → `initSetupSide(next)` или (все стороны готовы) → `PhaseManager.setPhase('rally')`.
- State: `currentScenario`, `setupSide`, `setupPool`, `setupSelectedTemplate`, `setupDiceRolled`.

### RPh (Rally Phase) — ПОЛНОСТЬЮ ГОТОВО
Подфазы (по сторонам: attacker → defender):
1. **Recovery** — выделяет unpossessed weapons в hex'ах, где есть infantry соотв. стороны. Клик на weapon → Attempt button → `rollRallyAttempt`. Auto-skip если нет кандидатов.
2. **Repair** — для broken weapons на possessor'е этой стороны. `rollRepairAttempt` → flip обратно (`flipRendering(toBroken=false)`). Auto-skip.
3. **Transfer** — передача оружия внутри стека. Клик на оружие (`idTransferSelectedUnit`), клик на инфантри в том же hex'e (`idUnitToGetWeapon`) → меняется possessorId. **UIState.showTransferPanel** (аналог CC-панели). Делать могут и те, кто уже делал Recovery/Repair.
4. **SelfRally** — только у юнитов с `selfRally:true` (am_667, leaders, crews). Клик → highlight → Attempt button. Auto-advance если никого.
5. **UnitRally** — остальные broken MMC, нужен leader в hex'e. DRM через `calcLeadershipDRM` (лучший = самый отрицательный). Auto-advance.
6. **DM-Removal (step h)** — все unbroken units с DM становятся highlighted; клик → `ToggleKeepDM` (DMkept=true, иначе снимается). После End-кнопки — DM снимается у всех non-kept.

- `rules.js`: `rollRallyAttempt` (единая для Self/Unit — параметризована), `rollRepairAttempt`, `calcLeadershipDRM` (экспортнута).
- Кнопки на grid: `Recovery` (10,100), `Repair` (10,150), `Transfer` (10,200), `SelfRally` (10,250), `UnitRally` (10,300). Attempt-кнопки — колонка x=310 на той же y.
- `fadeButton(label)` — opacity 0.5 + listening=false (вместо destroy — визуальная история пройденных подфаз).
- End-кнопка подфазы → fadeButton + старт следующей.

### MPh (Movement)
- Per-unit MF, leaderBonus, roadBonus.
- Woods-Road two-step (UseWoods/UseRoad), crestLine cost, Overstack check, Split MG, Double Time, Assault Movement, PlaceSmoke (ключ hex'а в формате `col-row` dash, не comma).
- Portage Points dynamic + CX -1 IPC.
- `checkIfAddingToMovementGroupIsValid` с русскоязычными логами отказов (pinned/broken/prepFired/movementCompleted/wrong hex/wrong side/moved-mix).
- **MOVE блокирован в hex с enemy infantry** (но в hex с одним только enemy weapon — легально).
- End-MPh cleanup: `hasStartedMoving`, `movementGroup`, `movementStackHex` — сбрасывается.
- `movedThisMPh` сбрасывается в конце AFPh.
- Для оружия `hasStartedMoving` ставится если **оружие** меняло hex в MPh (не possessor).

### APh (Advance)
- `SelectForAdvance` требует `nothingSelected` (нельзя переключать юниты, если выбран). Esc = DESELECT_ALL работает в APh.
- Клик на гекс → двигается, если легитимно. Юниты не ловят клики (чтобы случайно не переключить).

### CCPh (Close Combat) — полная реализация
- Базовая логика: SelectCCHex → showCCPanel → CCToggleUnit → ConfirmCCAttack → StartDefenderCC → ResolveCC → simultaneous apply.
- **Ambush** (`rules.calcAmbushDRM`, `rules.rollAmbush`, `rules.isAmbushEligibleHex`):
  - На StartDefenderCC если hex eligible → показывается кнопка `RollAmbush`.
  - Клик → `rollAmbush` → `State.ambushSide = 'attacker'|'defender'|null`. Если side определена:
    - round 1: ambusher применяет свой attack list (_resolveAmbushRound) → effects на противнике.
    - Survivors противника идут в round 2 (их attack list фильтруется — только живые атакующие).
    - round 2: применяется ответка.
  - `ccAmbushRound = 'round 1' | 'round 2' | null`.
  - Non-ambush: обычный simultaneous resolve.
- **Melee** (`inMelee` флаг): если после резолва обе стороны остались в hex'е (`check_if_both_sides_still_in_hex`) — помечаем выживших `inMelee=true`, hex остаётся в ccHexes, в следующий CCPh разрешается снова.
- `_finalizeCCHex` — чистит currentCCHex, панель, кнопки (без обнуления attack-списков — это делают SelectCCHex/ConfirmCCAttack).

## Save/Load (saveLoad.js)
- Один слот в localStorage. Кнопки `Save` (160,10), `Load` (310,10) на uiLayer.
- `STATE_FIELDS` — список полей State для persist.
- `UNIT_SKIP` — несериализуемые поля юнита (image, brokenImage, node, x, y, routPathHexes, hexToHexesCostsMap, routMinCostToShelter).
- `load`: destroy existing nodes → restore primitives → респаун юнитов → **ручное позиционирование без tween** (`node.position()` напрямую, минуя `setUnit('pos')`) — чтобы не было конфликта с flip-анимацией.
- Broken-картинка нужна синхронно: иначе `node.findOne('Image').image(brokenImage)` падал на unit с `broken:true` в сейве. Фикс — `createUnit` стал async + `await loadImage(brokenSrc)`.
- В load loop поле `broken` обрабатывается напрямую (image swap), не через `setUnit('broken')`, чтобы избежать race с render-подпиской.
