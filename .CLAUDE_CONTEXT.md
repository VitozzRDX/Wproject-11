## Архитектура
```
Click → Interpreter (RULES matching) → Engine (handlers) → State
                                             → UIState (event bus) → RendererUI
                                             → Rules (чистая математика)
```

- **State** (state.js) — данные + subscribers (fires on setUnit). `window.State` доступен.
- **PhaseManager** — 8 фаз: `rally`, `prepFire`, `movement`, `defensiveFire`, `advancingFire`, `rout`, `advance`, `closeCombat`.
- **Rules** (rules.js) — чистая математика. Импортит `PhaseManager`, НЕ импортит `State`.
- **Engine** — единственный кто мутирует State.
- **UIState** — event bus для UI (кнопки, крутилка, LoS, residual, smoke, rout/CC overlays, panels).
- **RendererUI** подписан на UIState, использует ТРИ слоя:
  - `uiLayer` — screen-fixed (кнопки, крутилка, CC-панель).
  - `worldFxLayer` — world-anchored ВЫШЕ юнитов (LoS, residual, smoke, rout overlays).
  - `ccLayer` — world-anchored ПОД юнитами (CC-хекс красная подсветка).
- **Renderer** подписан на State.setUnit.
- **Positioning** — стэкинг юнитов в hex'e.

## Coordinate System
- **Единая нумерация `"col-row"`**.
- `pixelToHex` — Voronoi-nearest (3×3 кандидатов).
- `hexDistance` — cube-based.
- `_hexLine` — pixel Bresenham + hex-spine resolution.
- `cubeRing(center, radius)` — hex'ы на кольце радиуса.
- `isAdjacent(a, b)` = `hexDistance === 1`.
- `bfsHexes` (не используется активно) + `dijkstraHexes` + `reconstructPath` — pathfinding generic.

## Scenarios

## Единая иерархия юнитов (unitloading.js)

## Реализованные фазы

### Rally (Rally Phase)
- Стартовая фаза loadScenario.
- Механики самого rally (rally rolls, self-rally) пока не реализованы.

### MPh (Movement)
- Per-unit MF, leaderBonus, roadBonus.
- Woods-Road two-step (UseWoods/UseRoad).
- crestLine cost.
- Overstack check.
- Split MG, Double Time, Assault Movement, PlaceSmoke.
- **Portage Points (dynamic):** `_portageExcess(u, units, mg)` — сравнивает `sum(possessedPP)` vs `IPC + SMC-bonus`, теперь также учитывает **CX -1 IPC** (baseIPC = ipc - (exhausted?1:0)).
- Drop/Recover кнопки.
- Cascade DFF: LoS, TEM, HA, hindrance, FFNAM, FFMO, LLMC/LLTC, IFT, CR/broken/wounded/reduced/quality_reduce/reduce_then_quality.

### PFPh (Prep Fire)
- Attacker стреляет по стоящим defender'ам.
- `prepFired=true` (оранжевая "PF"), CX cleared.
- В MPh юниты с prepFired не двигаются.

### DFPh (Defensive Fire — Final Fire)
- Defender стреляет по attacker-infantry в hex'e.
- `check_DFPh_FinalFire_valid`: FirstFire-стрелки только adjacent.
- FFNAM/FFMO негируются.
- Post: firingStatus → FinalFire. В конце фазы сбрасывается.

### AFPh (Advancing Fire)
- Attacker с half FP.
- `checkIfAddingToFireGroupIsValid` блокирует: prepFired, advFired, MMG/HMG при `possessor.hasStartedMoving`.
- Post: advFired=true (белая полоска "fired"). В конце сбрасывается.

### RtPh (Rout Phase) — **ПОЛНОСТЬЮ ГОТОВО**
- **Идентификация mustRout** при NextPhase entry: `Rules.mustRout` (broken + adj к unbroken enemy OR Open Ground + LoS от Good Order enemy). Кэш `keuIDsList` = `buildKEUList`.
- **SelectRouter** (клик по mustRout): MF=6, cache `hexToHexesCostsMap` (forward Dijkstra), `shelterHexes` (nearest-by-MF + fallback further-tier если все no-further-KEU). Кнопки EndRout + LowCrawl.
- **PickShelter** (клик по shelter): reverse Dijkstra `routMinCostToShelter`, коридор `routPathHexes`.
- **RoutMove** (клик по коридору):
  - Cost check → move → `mustRout=false` → escort leader тоже двигается.
  - Update KEU (только растёт).
  - Interdiction (если Open Ground + не LowCrawl): `_findInterdictor` (unbroken/unpinned enemy с unhindered LoS и в range) → `Rules.interdictionAttack(unit, escort)` (NMC с leader DRM, no FFMO). Outcome: eliminated/reduced/wounded/pinned/ok. Async `_handleInterdiction` с sleep(300).
  - Auto-end: reached chosenShelter && not adjacent unbroken enemy → safe finalize. Иначе clear destination + пересчёт.
  - Recompute corridor (KEU changed OR reached-invalid).
- **StartDefenderCC / EndRout / LowCrawl:** кнопки на UI.
- **ArmLowCrawl:** `pendingLowCrawl=true`. Следующий RoutMove: mf=0, `usedLowCrawl=true`, skip interdiction.
- **EndRout:** eliminate если adjacent-unbroken OR mustRout still true, иначе `_finalizeRout`.
- **Escort leader:** shift+клик по unpinned leader'у в hex'е router'а → `escortingRouter=routerId`. Двигается автоматом, `interdictionAttack` использует его leadershipModifier как DRM, при eliminated → тоже KIA.
- **`_replace_unit`** наследует MF + весь rout-state (chosenShelter, keuIDsList, routPathHexes и т.д.) → HS продолжает раут после CR.
- **KIA visual:** `_eliminateWithKIA` (State.setUnit('kia', true) → renderer показывает 'KIA' text, sleep(700), remove_unit). Используется во всех eliminations.
- **Visuals:** пунктир mustRoutRect (пока не выбран) → solid red inRoutingRect (при selection). Overlay: синие shelter'ы, фиолетовый коридор, зелёные fallback adjacent.

### APh (Advance Phase)
- NextPhase entry: reset MF для attacker Good Order infantry (`baseMF`, wounded leader → `min(baseMF, 3)`).
- **SelectForAdvance** (клик по attacker infantry Good Order): toggle `selectedForAdvance`. Клик по weapon → берём possessor'а.
- **Advance** (клик по adjacent hex): cost check → if cost === mf && !CX → set exhausted. Если CX + cost === mf → refuse. Move + possessed weapons. Woods-Road auto как road (1 MF).
- `_markCCHexIfEnemyPresent` — при advance в hex с enemy infantry, добавляет hex в `State.ccHexes`.
- Cleanup selectedForAdvance при выходе.

### CCPh (Close Combat Phase) — **MVP готов**
- **UI:** ccLayer (под юнитами) для красных CC-хексов.
- **Entry:** `NextPhase 'closeCombat'` — `UIState.setCCHexes(State.ccHexes)` (собран в APh handler'ом `_markCCHexIfEnemyPresent`).
- **SelectCCHex** (клик по красному хексу): устанавливает `currentCCHex`, показывает CC-панель (`UIState.showCCPanel(units)`), кнопки ConfirmCCAttack + StartDefenderCC. Reset attack lists.
- **CC-панель:** vertical Konva.Group на uiLayer со Konva.Image юнитов hex'а (размер как на карте). Attribute `ccPanel: true`, `unitId`.
- **CCToggleUnit** (клик по юниту в панели): проверка `ccSelectedIds.includes(uid)` → return. Кладёт в pool по стороне и declare-фазе:
  - attackerDeclare + attacker-юнит → `ccAttackerAttackers`
  - attackerDeclare + defender-юнит → `ccAttackerDefenders`
  - defenderDeclare + defender-юнит → `ccDefenderAttackers`
  - defenderDeclare + attacker-юнит → `ccDefenderDefenders`
  - Добавляет в `ccSelectedIds` (cumulative — сброс только на StartDefenderCC).
  - `State.setUnit('ccSelected', true)` → красная рамка на карте.
- **ConfirmCCAttack:** `_confirmAttackFromPools(attackers, targets, list)` → push {attackers, targets} в `ccAttackerList` или `ccDefenderList`, обнуляет pool'ы, гасит рамки.
- **StartDefenderCC:** `ccDefenderDeclaring=true`, `ccSelectedIds=[]` (новая declare-фаза). Добавляет кнопку ResolveCC.
- **ResolveCC:** async, вызывает `_result_of_CC_in_hex`.
  - `_calc_effect_for_targets_CC(list)` — для каждой группы: sum FP атакующих (`_ccUnitFP(u)` = 1 для leader, иначе firepower), sum FP целей, `ccOddsColumn` → `ccKillNumber` → `roll2d6` + leader DRM. Leader DRM применяется только если в attackers есть MMC (не solo-leader). Если leader'ов несколько — берётся лучший (min `leadershipModifier`). Возвращает `{uid: 'kia'|'reduce'}` (miss не пишется).
  - `_apply_effect_CC(effects)` — итерирует dict: 'kia' → `_eliminateWithKIA`, 'reduce' → `_replace_unit` (с halfSquad) или `_eliminateWithKIA` (если halfSquad нет).
  - **Simultaneous:** сначала считаем оба списка, потом применяем оба. Юнит успевает "выстрелить" до своей смерти.
  - `_finalizeCCHex` — убирает currentCCHex из ccHexes, чистит state, гасит панель + кнопки.
- **rules.js:** `ccOddsColumn(atkFP, defFP)` (ratio → колонка), `ccKillNumber(column)` (колонка → kill number). `roll2d6` экспортирован.
- **Отложено:** Ambush, Melee counter, CR random target selection (пока `Math.floor(random)` — простой рандом).
